# Precision trackpad scroll

- Status: in progress
- Date: 2026-09-06
- Scope: sixth Phase 5 production-input roadmap item
- Related: CAP-03, IN-06, SCR-07, IN-02

## Purpose

Add native macOS wheel and trackpad input to the product path without losing
fractional precise deltas or momentum events. Exactly one owner must consume
each scroll event: an application that enabled terminal mouse reporting, local
primary-screen scrollback, or alternate-screen cursor-key emulation.

## Background and confirmed facts

- The preceding mouse task owns down/up/move/drag normalization and xterm mouse
  reporting, but deliberately deferred wheel events, precise deltas, momentum,
  alternate-screen scroll-key emulation, and viewport movement to this item.
- `dart_appkit` protocol v4 currently has mouse event types 10--13 but does not
  receive `NSEventTypeScrollWheel`. Extending an old protocol version would let
  a newly built native host send an event type that an older Dart client cannot
  decode, so the scroll event requires an opt-in protocol v5 addition.
- AppKit exposes `scrollingDeltaX/Y`, `hasPreciseScrollingDeltas`, `phase`,
  `momentumPhase`, and `isDirectionInvertedFromDevice` on scroll-wheel events.
  Apple documents that legacy wheel events have no phase; physical trackpad
  streams use gesture phases, while momentum streams use `momentumPhase` and a
  `none` gesture phase.
- xterm documents wheel buttons 4/5 as the ordinary button codes plus 64 and
  omits release reports. Without application mouse reporting, wheel input
  scrolls history; its Alternate Scroll behavior maps wheel direction to cursor
  up/down while the alternate screen is visible.
- `TerminalViewport.scrollByRows` already uses a positive value to move toward
  older primary history and clamps at both ends. The alternate screen has no
  scrollback offset.
- Primary specifications:
  - <https://developer.apple.com/documentation/appkit/nsevent>
  - <https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html>
  - <https://invisible-island.net/xterm/ctlseqs/ctlseqs.html>

## Ordered subtasks and dependencies

1. **`dart_appkit` event protocol v5 and bounded scroll event boundary**
   - Add an opt-in event type whose immutable Dart representation preserves
     logical content-view position, finite X/Y deltas, precise/non-precise
     classification, gesture and momentum phases, direction inversion state,
     and stable modifiers.
   - Keep protocols v1--v4 byte/list compatible and prevent v4 clients from
     receiving the new event. Cover native capture, C-object encoding, Dart
     decoding, malformed values, and protocol negotiation.
   - Completion: all `dart_appkit` tests and format/analyze gates pass, then the
     dependency change is committed separately.
2. **Precision/momentum accumulator and exclusive routing**
   - Convert precise pixel deltas to fractional terminal rows using the current
     cell height and accumulate sub-row motion; treat non-precise deltas as row
     units. Bound every event and emitted action count, reset residuals at
     stream boundaries/direction changes, and never replay elapsed momentum.
   - Route active application mouse tracking to xterm wheel press reports, Shift
     override or a normal primary screen to local history, and a non-reporting
     alternate screen to bounded cursor up/down input. One source event may
     choose only one route.
   - Completion: focused unit tests cover phase transitions, fractional motion,
     direction changes, wheel packets in every encoding, Shift override,
     primary/alternate behavior, bounds, and malformed geometry.
3. **Real AppKit product integration and both-runtime acceptance**
   - Subscribe the live pane to `AppKitScrollEvent`, use live font/grid metrics
     and terminal modes, write generated bytes through the bounded pane PTY
     queue, and request a fresh viewport render for local scrolling.
   - Extend the raw AppKit acceptance injector with deterministic scroll events.
     Prove local primary history scroll, terminal wheel packets, alternate-screen
     key emulation, fractional accumulation, momentum continuation, Shift
     override, and no duplicate consumption in Developer JIT and Release AOT.
   - Completion: both real-window runtime modes, full Dart/native tests, bundle
     audits, smoke, and resource checks pass; then complete the parent item.

The subtasks are strictly ordered. The product cannot consume a scroll event
until the dependency protocol is committed, and product acceptance depends on
the pure routing contract. No clipboard, hyperlink, or accessibility behavior
is implemented early.

## Scope

- Native AppKit vertical/horizontal scroll event capture with stable phase data.
- Vertical line accumulation for precise trackpads, legacy wheels, and momentum.
- Xterm-compatible vertical wheel-up/wheel-down reports at the pointer cell.
- Local primary scrollback and alternate-screen cursor-key emulation.
- Shift local-scroll override while terminal mouse tracking is enabled.
- Bounded output/action counts and deterministic real-window acceptance.

## Out of scope

- Elastic overscroll, visual scrollbars, kinetic animation invented outside the
  native AppKit event stream, horizontal history, zoom, or font-size gestures.
- Configurable scroll multipliers, alternate-scroll preference UI, mouse
  buttons 6--11, Kitty extensions, or application-specific smooth-pixel mouse
  protocols.
- Clipboard/paste, hyperlinks, accessibility, search, or selection changes.

## Dependencies and risks

- The native and Dart event codecs must change atomically inside `dart_appkit`;
  protocol v5 is the compatibility gate and protocols v1--v4 must remain usable.
- Precise deltas are in pixel-like units while legacy wheel deltas are line-like;
  treating both identically would make one device class unusably slow or fast.
- Scroll streams can contain zero-delta phase boundary events and interleaved
  physical/momentum phases. State must not manufacture output at boundaries.
- A single AppKit event can otherwise reach both terminal mouse reporting and
  local scrollback. The router result is the ownership proof.
- Large native deltas must not create an unbounded list or PTY write burst.

## Completion conditions

- Real scroll events arrive through protocol v5 with finite, validated values;
  older protocol fixtures and negotiation remain unchanged.
- Fractional precise motion is retained across compatible events, momentum is
  consumed exactly once, phase boundaries are deterministic, and per-event work
  is bounded.
- Normal primary output scrolls locally, active mouse tracking receives only
  wheel reports, Shift forces only local history, and non-reporting alternate
  screen input receives only cursor keys.
- Developer JIT and Release AOT real-window acceptance prove the same behavior,
  with no duplicate PTY bytes or local movement.
- Required docs, README, feature matrix, roadmap state, and one commit per
  subtask are complete.
